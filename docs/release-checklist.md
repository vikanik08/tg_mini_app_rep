# Release Checklist

Короткий чек-лист перед staging или первой выкладкой mini app.

## 1. Техпроверка

- Поднят backend и база:
  - `docker compose up -d --build`
- Backend отвечает:
  - `curl http://localhost:8000/health`
- Миграции применены:
  - `docker compose exec backend sh -lc "cd /app && alembic upgrade head"`
- Frontend собирается:
  - `cd frontend`
  - `npm run lint`
  - `npm run build`

## 2. Env и секреты

- В `backend/.env.local` задан нормальный `JWT_SECRET`, не `change_me`
- `ALLOW_DEV_LOGIN=true` используется только локально
- В staging/prod `VITE_USE_DEV_LOGIN=false`
- `CORS_ORIGINS` содержит реальный frontend URL
- Секреты не лежат в tracked `.env`

## 3. Основной smoke

- Открывается `/` без белого экрана
- Добавляется первый питомец
- Фото питомца можно не загружать
- Питомец сохраняется без `401`
- Из главной открывается паспорт активного питомца
- Из главной открывается календарь
- На мини-календаре можно выбрать день
- В большом календаре можно добавить напоминание
- Напоминание видно:
  - в календаре
  - на главной
  - в профиле
  - в паспорте питомца

## 4. CRUD событий

- Событие можно создать
- Событие можно отредактировать
- Событие можно отметить выполненным
- Выполненное событие можно вернуть в план
- Событие можно удалить
- После каждого действия показывается понятный toast

## 5. Проверка нескольких питомцев

- Можно создать второго питомца
- Переключение активного питомца работает:
  - на главной
  - в профиле
- `/passport` ведет в паспорт активного питомца
- Фильтр `Активный питомец / Все питомцы` работает:
  - в календаре
  - в профиле

## 6. Ручные edge cases

- Обновление страницы на `/passport/:petId` не ломает экран
- Обновление страницы на `/calendar?date=...` сохраняет выбранный день
- Переход назад из создания питомца не ведет в пустой экран
- При остановленном backend показывается понятная boot error карточка

## 7. Ветпаспорт и здоровье

- Базовые данные питомца сохраняются и отображаются: имя, пол, дата рождения, порода, окрас, вес
- Медицинская информация отображается после сохранения
- Особенности здоровья и операции раскрываются списком и не ломают контейнеры длинным текстом
- PDF ветпаспорта открывается и содержит приписку SmartPet
- Контроль здоровья открывается с главной и из раздела питомца
- Проверка здоровья сохраняется в историю и создает следующее ежемесячное напоминание

## 8. Telegram перед релизом

- Проверен реальный `initData` flow внутри Telegram
- Web App URL настроен на нужный frontend
- Bot token и webhook/infra значения актуальны
- Поведение вне Telegram либо запрещено, либо корректно объясняется

## 9. Готово к выкладке, если

- `lint` зеленый
- `build` зеленый
- нет блокирующих `401/403/500`
- основной пользовательский сценарий проходит от добавления питомца до работы с событиями
- staging ссылка открывается и работает на мобильном сценарии
